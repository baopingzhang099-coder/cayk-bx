## 二、实施策略

### 2.1 核心原则

1. **弹窗优先**：所有新增/查看/编辑/变更交互优先使用 TDesign Dialog 组件，不新增路由
2. **Mock驱动**：当前所有数据走 Pinia store 的 mock 数据层，API层后续替换
3. **强校验 + 风险提示**：合规规则采用前端强校验（阻断提交）+ 状态约束 + 风险提示组合
4. **按模块推进**：保单管理模块 → 理赔模块 → 规则引擎 → 基础设施

### 2.2 技术方案

| 需求 | 技术选型 | 说明 |
| --- | --- | --- |
| 图表展示 | ECharts 5 (vue-echarts) | 折线图/柱状图/饼图用于统计页面 |
| OCR模拟 | TDesign Upload + 表单 | 上传保单/批单PDF/图片，展示OCR提取结果编辑界面 |
| 规则引擎 | Pinia getter + 工具函数 | 纯前端规则校验，通过computed属性驱动UI状态 |
| 表格增强 | TDesign Table 内置功能 | 排序、筛选、导出CSV |
| 弹窗表单 | TDesign Dialog + Form | 统一使用Dialog承载表单，宽度500-800px |
| API层 | Axios + 请求/响应拦截器 | 统一错误处理、loading状态、token管理 |

## 三、详细实施计划

### V2-1：保单管理增强（预计8小时）

#### 任务1.1：保单数字化OCR弹窗（2h）

**文件**：`src/pages/policy/PolicyList.vue`（新增OCR弹窗组件可抽离为 `src/components/business/PolicyOcrDialog.vue`）

**功能**：
1. 保单列表"新增投保"按钮 → 弹出OCR弹窗（800px）
2. Tab1-上传：Upload组件上传保单/批单文件（PDF/JPG/PNG）
3. Tab2-校对：展示OCR提取字段（25+字段）供人工校对
   - 基础信息：保单号、保险公司、保险人、被保险人、受益人、起止期等
   - 责任限额：最高赔偿限额、买方信息（多买方）、信用限额、免赔额等
   - 申报规则：申报方式、周期、截止日期、币种
   - 费用管理：费率、缴费期限、保费、退保费用
4. 一致性校验：被保险人名称与贸易项下卖方信息强校验
5. 保存：结构化数据存入 store

**字段定义**：见 PRD §3.16

#### 任务1.2：续保申请弹窗（1.5h）

**文件**：`src/pages/policy/PolicyList.vue`（新增 `RenewalDialog.vue`）

**功能**：
1. 保单即将到期前30天 → 列表展示"续保"操作按钮
2. 点击续保 → 弹窗（700px）展示续保表单
3. 字段：申请日期（自动）、原保单到期日（自动读取）、续保期间、预计可保营业额、投保比例（≤90%）
4. 系统自动计算：上年度申报总额、赔付率、限额利用率
5. 附件上传：续保申请书、上年度出运申报汇总、收汇/逾期情况
6. 空窗期提示：如果存在空窗期，展示风险提示

**字段定义**：见 PRD §3.13.6

#### 任务1.3：退保申请弹窗（1h）

**文件**：`src/pages/policy/PolicyList.vue`（新增 `SurrenderDialog.vue`）

**功能**：
1. 保单列表"退保"操作按钮
2. 弹窗（600px）展示退保申请表单
3. 字段：申请日期（自动）、退保原因、退保生效日期、已生效月数（自动计算）、短期费率、应退保费金额
4. 附件上传：退保申请书
5. 联动：退保后保单状态更新为"退保"

**字段定义**：见 PRD §3.13.7

#### 任务1.4：保单变更弹窗（1.5h）

**文件**：`src/pages/policy/PolicyList.vue`（新增 `PolicyChangeDialog.vue`）

**功能**：
1. 保单列表"变更"操作按钮
2. 弹窗（700px）展示变更申请表单
3. 变更类型下拉：增加买方/减少买方/延期/变更限额/变更被保险人信息/变更联系人/变更地址/其他
4. 字段：关联保单号（只读）、变更申请日期（自动）、变更类型、变更原因、变更前内容、变更后内容
5. 附件上传：变更申请书、证明文件（按变更类型要求）

**字段定义**：见 PRD §3.13.5

#### 任务1.5：限额申请表单扩展（1h）

**文件**：`src/pages/policy/CreditLimit.vue`

**改进**：
1. "申请限额"按钮 → 弹窗（700px）承载完整限额申请表单
2. 新增字段：付款条件（账期天数）、支付方式、过去12个月赊销交易额、预计未来12个月销售总额
3. 新增字段：是否有担保、担保方全称、与该买方合作年限
4. 附件上传：历史交易记录、买方资质证明
5. 下拉选择：是否同意联系买方

**字段定义**：见 PRD §3.13.3

#### 任务1.6：出运申报字段补齐 + 保费管理视图（1h）

**文件**：`src/pages/policy/ShipmentDeclare.vue`

**改进**：
1. 新增字段：发票号、发票金额、发票日期、应付款日（系统自动计算）、货物描述、运输方式、提单号/运单号、已用限额余额、申报批次号
2. 附件上传：商业发票、提单/运单、报关单、买方收货凭证
3. 按保险公司展示申报截止日提示（见 PRD §3.14）

**保费管理视图**：保单详情页新增"保费管理"子标签，展示13个保费字段

### V2-3：业务规则引擎（预计6小时）

#### 任务3.1：超限拦截（1h）
- **位置**：ShipmentDeclare.vue 提交申报时
- **逻辑**：申报金额 > 买方剩余可用限额 → 弹窗阻断 + "超限额"提示

#### 任务3.2：保费未缴冻结（1h）
- **位置**：ShipmentDeclare.vue + PolicyList.vue
- **逻辑**：保费超期未缴 → 冻结该保单下所有出运申报权限 → 红色提示条

#### 任务3.3：续保空窗期控制（0.5h）
- **位置**：ShipmentDeclare.vue
- **逻辑**：到期前30天提醒；空窗期内暂停出运申报 + 风险提示

#### 任务3.4：闲置预警/撤销（1h）
- **位置**：CreditLimit.vue
- **逻辑**：距上次出运>60天 → 黄色预警标签；>90天 → 自动撤销 + 不可逆提示

#### 任务3.5：集中度限制（0.5h）
- **位置**：CreditLimit.vue 限额申请时
- **逻辑**：CPIC规则：单一买方≤20%、单一国家≤30%

#### 任务3.6：8家公司差异化申报规则展示（1h）
- **位置**：ShipmentDeclare.vue
- **实现**：根据保单关联的保险公司，自动展示对应的申报截止日/方式/逾期处理提示

#### 任务3.7：4家公司差异化理赔规则展示（1h）
- **位置**：ClaimProcess.vue
- **实现**：按保险公司展示不同报案时限/资料要求/调查时限/赔付时限

## 六、设计决策记录

| 决策 | 选项 | 选择 | 原因 |
| --- | --- | --- | --- |
| OCR实现方式 | 真实OCR / 模拟OCR | 模拟OCR | 当前阶段无后端OCR服务，采用上传文件后手动编辑字段的模式 |
| 弹窗 vs 抽屉 | Dialog / Drawer | Dialog（弹窗） | 保持交互一致性，避免抽屉嵌套问题 |
| 规则引擎位置 | 前端 / 后端 | 前端（V2-3阶段） | API层尚未实现，先在前端做纯JS规则校验，后续可迁移至后端 |
| 图表库 | ECharts / AntV / Chart.js | ECharts | 社区成熟度高、文档丰富、满足折线图/柱状图/饼图需求 |
| 状态管理扩展 | Pinia / composables | Pinia | 已有business store，扩展即可 |
