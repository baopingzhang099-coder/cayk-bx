## 二、保单管理生命周期全链路设计方案

### 2.1 整体架构

保单管理生命周期分为**七大核心阶段**，覆盖保单从录入到维护的全过程：

```
阶段一：保单导入与合同签署
    ├── 1.1 保单录入/数字化（OCR + 人工校对）
    ├── 1.2 合同签署（在线电子签章）
    ├── 1.3 保费支付（扫码/转账/在线）
    └── 1.4 保单生效/激活（状态更新）

阶段二：信用限额管理
    ├── 2.1 限额申请（买方信息录入）
    ├── 2.2 资信调查（第三方征信调用 + 集中度校验）
    ├── 2.3 限额审批（保险公司在线批复）
    ├── 2.4 增额申请（历史交易佐证）
    └── 2.5 限额动态管理（闲置60天预警/90天撤销/逾期冻结）

阶段三：出运申报与收汇跟踪
    ├── 3.1 出运申报（发票号/金额/日期录入）
    ├── 3.2 申报校验（余额校验 + 时限校验）
    ├── 3.3 保费核定与缴纳（10工作日内）
    └── 3.4 收汇跟踪（逾期天数自动计算）

阶段四：逾期与理赔
    ├── 4.1 逾期监控（85天预警/90天报损）
    └── 4.2 启动理赔（关联理赔流程）

阶段五：保单维护
    ├── 5.1 保单变更（批改）
    ├── 5.2 续保管理（到期前30天预警）
    └── 5.3 退保管理（提前30天申请）

阶段六：RWA金融同步（跨模块联动）
    ├── 保单资产登记
    ├── 限额额度共享
    ├── 理赔回款清算
    └── 退保结算同步
```

### 2.3 保单生命周期流程管理页面（已实现）

**页面**：`src/pages/policy/PolicyProcess.vue`

**设计说明**：
1. 采用**横向7步进度条 + 竖向时间线**的双层设计
2. 7个步骤依次为：合同签署 → 保费支付 → 核保材料提交 → 保单生效流程 → 信用限额管理 → 出运申报管理 → 保单维护
3. 每个步骤支持折叠/展开、审批结论和意见录入
4. 步骤状态：已完成（绿色勾）、进行中（蓝点高亮）、待处理（灰色）

**已实现的7个步骤内容**：

| 步骤 | 内容 | 数据来源 | 审批操作 |
| --- | --- | --- | --- |
| Step 1 合同签署 | 合同编号、保单号、被保险人、投保买方信息、合同状态、保险金额 | `contractData` computed | ✅ 审批结论+意见 |
| Step 2 保费支付 | 应付保费、支付方式选择、支付状态、支付凭证上传 | `formData.step2` | ✅ 审批结论+意见 |
| Step 3 核保材料提交 | 投保申请书/已签署合同/保费支付凭证/贸易合同副本/买方资信报告/商业发票复选框 | `formData.step3` | ✅ 审批结论+意见 |
| Step 4 保单生效流程 | 4子步骤（保单出具→信息上传→缴费凭证→保险生效）+ 保单信息详情 | `formData.step4` | ✅ 审批结论+意见 |
| Step 5 信用限额管理 | 限额概览表格（含使用率进度条） | `creditLimitData` | ✅ 审批结论+意见 |
| Step 6 出运申报管理 | 出运统计（总笔数/总金额/已申报/待申报）+ 申报规则 | `shipmentStats` | ✅ 审批结论+意见 |
| Step 7 保单维护 | 维护类型（续保/变更/退保）选择、申请说明、附件上传 | `formData.step6` | ✅ 审批结论+意见 |

## 三、实施策略

### 3.1 核心原则

1. **弹窗优先**：所有新增/查看/编辑/变更交互优先使用 TDesign Dialog 组件，不新增路由
2. **Mock驱动**：当前所有数据走 Pinia store 的 mock 数据层，API层后续替换
3. **强校验 + 风险提示**：合规规则采用前端强校验（阻断提交）+ 状态约束 + 风险提示组合
4. **按模块推进**：保单管理模块 → 理赔模块 → 规则引擎 → 基础设施

### 3.2 技术方案

| 需求 | 技术选型 | 说明 |
| --- | --- | --- |
| 图表展示 | ECharts 5 (vue-echarts) | 折线图/柱状图/饼图用于统计页面 |
| OCR模拟 | TDesign Upload + 表单 | 上传保单/批单PDF/图片，展示OCR提取结果编辑界面 |
| 规则引擎 | Pinia getter + 工具函数 | 纯前端规则校验，通过computed属性驱动UI状态 |
| 表格增强 | TDesign Table 内置功能 | 排序、筛选、导出CSV |
| 弹窗表单 | TDesign Dialog + Form | 统一使用Dialog承载表单，宽度500-800px |
| API层 | Axios + 请求/响应拦截器 | 统一错误处理、loading状态、token管理 |

### V2-1：保单管理增强（预计8小时）

#### 任务1.1：保单数字化OCR弹窗（2h）

**文件**：`src/pages/policy/PolicyList.vue`（新增OCR弹窗组件可抽离为 `src/components/business/PolicyOcrDialog.vue`）

**功能**：
1. 保单列表"新增投保"按钮 → 弹出OCR弹窗（800px）
2. Tab1-上传：Upload组件上传保单/批单文件（PDF/JPG/PNG）
3. Tab2-校对：展示OCR提取字段（25+字段）供人工校对
   - 基础信息：保单号、保险公司、保险人、被保险人、受益人、起止期等
   - 责任限额：最高赔偿限额、买方信息（多买方）、信用限额、免赔额等
   - 申报规则：申报方式、周期、截止日期、币种

4. 一致性校验：被保险人名称与贸易项下卖方信息强校验
5. 保存：结构化数据存入 store

**字段定义**：见 PRD §3.16

## 六、设计决策记录

| 决策 | 选项 | 选择 | 原因 |
| --- | --- | --- | --- |
| OCR实现方式 | 真实OCR / 模拟OCR | 模拟OCR | 当前阶段无后端OCR服务，采用上传文件后手动编辑字段的模式 |
| 弹窗 vs 抽屉 | Dialog / Drawer | Dialog（弹窗） | 保持交互一致性，避免抽屉嵌套问题 |
| 规则引擎位置 | 前端 / 后端 | 前端（V2-3阶段） | API层尚未实现，先在前端做纯JS规则校验，后续可迁移至后端 |
| 图表库 | ECharts / AntV / Chart.js | ECharts | 社区成熟度高、文档丰富、满足折线图/柱状图/饼图需求 |
| 状态管理扩展 | Pinia / composables | Pinia | 已有business store，扩展即可 |
